# Dynamic daily owner: explicit local integration, not deployed

Base af1c085. There is no workflow/CLI activation or network operation in this
change. Tests supply synthetic HTTP and local bare Git. A `durable_owner` must be
explicitly constructed and injected into the real `collect_request` call.

## Implemented seams

- `load_request_source` reads exact original bytes/blob from an immutable control
  commit, uses the existing `_load_request` schema/contract checks and the existing
  first-introduction/ancestry rules. It does not require an old collection result.
- Source proof describes the supplied repository, not proof that its owner or the
  invoking workflow is authorized. Production activation still must bind the real
  control repository, caller and shared collector lock. The current control/compute
  workflow uses shallow checkouts; first-introduction requires a full control
  history and a valid `origin/discovery-requests` ref. Workflow is not changed here.
- StorePublisher gains an optional constrained report namespace. Its baseline
  default, baseline report method and verifier remain unchanged. Dynamic owner
  uses its own namespace/mode and the existing generic durability verifier.
- Per symbol: atomically publish conservative credit + immutable business-ID/symbol
  claim, verify durability, invoke the existing budget/claim guard immediately
  before bounded HTTP open, durably publish exact raw before parsing, then close
  normalized evidence, real index/shards/quarantine and terminal in the manifest.
  The guarded branch never calls post-fetch consume. Unguarded behavior remains.
- Each completed symbol leaves a clean checkout and advances the same exact head.
  Next symbol and original intraday require that clean boundary.
- Known strict parse rejection or trusted price revision can create a terminal
  closure. Unknown local storage/half-written market state or publication errors
  latch the owner and escape all collection handlers. No fallback final manifest,
  retry, refund or second push is generated by this path.

## Outcome and fee semantics

`requests_attempted` increments in the guard callback, not on reservation.
DEBIT_CONFIRMED_NO_HTTP counts the conservative reservation even if the minute
expires after verification. NOT_DEBITED, LOCAL_DEBIT_UNPUBLISHED and
DEBIT_UNCONFIRMED are not collapsed into a false zero-fee statement. Reserving a
credit does not establish an actual provider charge. A lost response after HTTP
can still leave only a durable claim/debit; same-business-ID/symbol reentry is
forbidden and requires explicit, evidenced recovery, not automatic recollection.

## Not implemented / not claimed

- Production caller/platform attestation, registration, secret setup or activation.
- Any fixed-universe, schedule, quota or shared daily-parser change.
- Remote predebit or retry changes inside the independent intraday collector.
  Daily closes cleanly before handing back to the original intraday/final writer.
- Inventory rebuild remains the existing final workflow step; these intermediate
  durable symbol commits are not a claim of report completeness or production
  acceptance. No automatic report trigger is introduced.
- Recovery of bytes when bounded transport itself rejects incomplete/oversize
  bodies, status/media errors, or a process dies before retention.
